# Как строится маршрут и считается время

Обзор всей цепочки: от настроек в панели до линии на карте и времени в пути. Построчный разбор самих профилей BRouter (какой тег сколько стоит, ссылки на строки `.brf`) лежит в [profiles.md](profiles.md). Результаты подбора чисел: [routing-calibration-2026-11-12.md](routing-calibration-2026-11-12.md), [routing-calibration-2026-11-13.md](routing-calibration-2026-11-13.md), [routing-cycleways-2026-11-12.md](routing-cycleways-2026-11-12.md).

Состояние на 13.11.2026.

## 1. Цепочка целиком

1. Маршрут состоит из точек. Каждая пара соседних точек называется «плечом» (leg) и считается отдельным запросом. Поэтому перетаскивание точки пересчитывает только два плеча вокруг неё. Код: `src/lib/brouter.ts`, `fetchLeg`.
2. Настройки панели превращаются в параметры профиля `profile:<имя>=<значение>`, функция `optionsToParams` (раздел 3).
3. Запрос идёт в maps-api (`/maps/api/route`). Там стоят очередь, лимиты и кэш (раздел 6), а за ними BRouter 1.7.10 с четырьмя профилями `nk-road`, `nk-gravel`, `nk-mtb`, `nk-hike`.
4. Для «Ищу подъёмы» и «Держаться тепловой карты» приложение берёт несколько вариантов маршрута и само выбирает лучший (раздел 5).
5. По готовой линии строится профиль высот: расстояние, высота, уклон и покрытие в каждой точке. По нему считаются набор, доли покрытий и время в пути (раздел 7).

Прямой отрезок (режим «прямые линии» или Shift+клик) роутер не вызывает: высоты берутся из тайлов рельефа.

## 2. Профили и как роутер выбирает дорогу

BRouter ищет путь минимальной «стоимости». Стоимость участка = длина × `costfactor` + штраф за рельеф.

- `costfactor` = 1 значит «стоит как своя длина». 3 значит, что роутер согласится на объезд до трёх раз длиннее по дороге с коэффициентом 1. 10000 и больше значит «нельзя».
- Рельеф: `uphillcost` добавляет условные метры за каждый метр набора. Например, 80 значит, что 100 м подъёма стоят как 8 км ровной дороги. Уклоны ниже `uphillcutoff` (в процентах) не штрафуются. Для спусков то же самое: `downhillcost` и `downhillcutoff`.

Профили сгенерированы из стандартных профилей BRouter скриптом `vps/stacks/brouter/profiles/gen.py`:

| Тип | Базовый профиль | Характер базового профиля |
|---|---|---|
| Road | fastbike | основные дороги дешёвые (primary 1,2, tertiary 1,0), грунт почти запрещён |
| Gravel | gravel | дороги дорогие (primary 4,8, secondary 4,2, tertiary 3,6), track 1,0; без велодорожки или велосипедного маршрута ещё ×1,85 |
| MTB | mtb | тропы и грунт дешевле дорог, учитывается mtb:scale |
| Hike | hiking-mountain | тропы по шкале SAC, дороги дорогие |

### Добавки nk_* (gen.py)

Генератор дописывает в конец каждого профиля свой блок. Шаги применяются по порядку, запрещённые участки (`costfactor` > 9997) не трогаются.

**Признаки участка:**
- `nk_paved` («асфальт»): `surface` из списка paved, asphalt, concrete, paving_stones, sett, ИЛИ `surface` не задан, а `highway` относится к дорогам (motorway…service, cycleway, pedestrian).
- `nk_goodgravel` («хороший грунт»): не асфальт и `surface` gravel, fine_gravel, compacted, unpaved, pebblestone, или `tracktype` grade1–grade3.
- `nk_quiet` («тихая дорога»): асфальт и `highway` tertiary, unclassified, residential, living_street, service, track, cycleway, road.
- `nk_mid` («средняя дорога»): асфальт и secondary.
- `nk_is_cycle` («велоинфраструктура»): cycleway, bicycle=designated, велополоса с любой стороны, велоулица, любой велосипедный маршрут (icn, ncn, rcn, lcn).
- `nk_busy` («загруженная дорога»): trunk, primary, secondary, tertiary.

**Шаг 1. Потолки стоимости** (первое подходящее правило):
```
если nk_heat_cap > 0 и асфальт, кроме trunk и motorway:   cf = min(cf, nk_heat_cap)
иначе если nk_gravel_cap > 0 и хороший грунт:               cf = min(cf, nk_gravel_cap)
иначе если nk_quiet_cap > 0 и тихая дорога:                 cf = min(cf, nk_quiet_cap)
иначе если nk_quiet_cap > 0 и средняя дорога:               cf = min(cf, 1,7 × nk_quiet_cap)
```
В Gravel по умолчанию `nk_gravel_cap` = 1,1 и `nk_quiet_cap` = 1,3: тихий асфальт почти так же дёшев, как хороший грунт, но грунт всё же выигрывает. Primary в Gravel ограничения не получает и остаётся около 9.

**Шаг 2. Покрытие:**
```
nk_mult = 1                  при nk_surface = 0
nk_mult = nk_surf_k          для грунта при nk_surface = -1 (асфальт остаётся 1)
nk_mult = nk_surf_k          для асфальта при nk_surface = 1 (грунт остаётся 1)
cf = cf × nk_mult
```

**Шаг 3. Велоинфраструктура** (когда `nk_cycle` = 1):
```
не велоинфраструктура:          cf = cf × nk_cycle_pen × (nk_busy_pen, если дорога загруженная)
велоинфраструктура:             cf = max(1, cf × nk_cycle_mult)
```
По умолчанию: Road `nk_cycle_pen` 1,5 и `nk_cycle_mult` 0,6; Gravel `nk_cycle_pen` 2,0; `nk_busy_pen` 1,0; в MTB и Hike `nk_cycle` = 0. Числа подобраны по тепловой карте Strava (калибровка 13.11.2026).

**Шаг 4. Запреты** (галочки «Может использовать»): если запрещено, участок получает 10000.

| Параметр | Что запрещает |
|---|---|
| `nk_allow_steps` = 0 | лестницы |
| `nk_allow_ferry` = 0 | паромы |
| `nk_allow_busy` = 0 | trunk и primary без велоинфраструктуры |
| `nk_allow_unpaved` = 0 | всё, что не асфальт (только Road) |
| `nk_allow_paths` = 0 | path, footway, bridleway без велоинфраструктуры |

**Рельеф:** `nk_uphillcost` и `nk_uphillcutoff` больше или равные 0 заменяют значения профиля, -1 оставляет родные.

## 3. Настройки панели → параметры

| Настройка | Параметры |
|---|---|
| Покрытие «Только асфальт» (-2) | nk_surface -1, nk_surf_k 6, nk_cycle_pen 1,2 |
| «Больше асфальта» (-1) | nk_surface -1 (k 2,5), nk_cycle_pen 1,4 |
| «Любое» (0) | ничего |
| «Больше грунта» (1) | nk_surface 1 (k 2,5) |
| «Тропы» (2) | nk_surface 1, nk_surf_k 5, nk_cycle_pen 1 |
| Подъёмы «Избегать» | nk_uphillcost 300, nk_uphillcutoff 1 |
| «Меньше» | nk_uphillcost 120, nk_uphillcutoff 1,5 |
| «Обычно» | профиль как есть |
| «Неважно» | nk_uphillcost 0 |
| «Ищу подъёмы» (подсказка про Погачара) | nk_uphillcost 0 и выбор самого холмистого варианта (раздел 5) |
| Предел крутизны N % | nk_uphillcutoff N, nk_uphillcost 600 (заменяет «Подъёмы») |
| «Велодорожки» выключены | nk_cycle 0 |
| «Держаться тепловой карты» | выбор варианта по тепловой карте (раздел 5) |
| Hike: сложность SAC | SAC_scale_limit (по умолчанию T3) |
| Hike: размеченные тропы | hiking_routes_preference 1 |
| Hike: лес и вода | consider_forest 1, consider_river 1 |
| Hike: подальше от дорог | consider_noise 1, consider_town 1 |
| «Может использовать» | nk_allow_* = 0 для снятых галочек |

Покрытие и велодорожки связаны: при «Только асфальт» штраф за отсутствие велоинфраструктуры смягчён до 1,2. Иначе короткий кусок дороги без велополосы проигрывает объезду по грунту.

**Ограничение:** «Только асфальт» означает сильное предпочтение (грунт в 6 раз дороже), а не запрет. Если асфальтового пути нет или он сильно длиннее, в маршрут попадёт track или path. Полный запрет грунта есть только в Road (`nk_allow_unpaved`).

## 4. Варианты маршрута BRouter

На запрос с `alternativeidx` 0…3 BRouter отдаёт до четырёх разных путей: 0 лучший, остальные следующие по стоимости. Часто 2 и 3 повторяют 0: на коротких плечах разных путей мало.

## 5. «Ищу подъёмы» и «Держаться тепловой карты»

Оба режима работают в приложении (`pickAlternative` в `brouter.ts`), это не параметры профиля. Приложение запрашивает несколько вариантов плеча и выбирает:

```
кандидаты не длиннее 1,3 × длины первого варианта
балл = (набор / набор первого, если «подъёмы») + (тепло / тепло первого, если «тепловая карта»)
побеждает вариант с баллом выше лучшего на 3 % и больше (меньшее считается шумом)
```

«Тепло» означает среднюю яркость тепловой карты Ride with GPS вдоль линии: точки через 30 м, тайлы z14, в каждой точке самый яркий пиксель в окрестности ±1 пиксель (около 10 м). Яркость = 1 − min(G, 192)/192 по зелёному каналу (жёлтый = мало поездок, красный = много), затем 0,25 + 0,75 × яркость там, где есть хоть какой-то след, и 0, где следа нет. Код: `src/lib/rwheat.ts`, `heatAlong`.

**Какие варианты запрашиваются:**
- «Ищу подъёмы»: варианты 0–3.
- «Тепловая карта»: варианты 0 и 1 как обычно, плюс 0 и 1 с `nk_heat_cap` = 1,6. С этим параметром любой асфальт, кроме trunk, стоит не дороже 1,6. Класс дороги перестаёт решать, и в кандидаты попадают основные дороги, где ездят много. Иначе Gravel обходит их из-за стоимости primary около 9.
- Оба режима сразу: варианты 0–3 плюс два с ограничением.

**Проверка 13.11.2026:** 9 плеч (Лиссабон и окрестности, Гарц) × 3 настройки (Gravel, Gravel «только асфальт», Road). Средняя «горячесть» выбранного варианта выросла с 0,76 до 0,86. Например, Лурес–Бусеаш на гравии: 0,55 → 0,88. Аленкер–Бусеаш, «только асфальт»: 0,50 → 0,94. Заметно хуже стал один случай: Аленкер–Бусеаш на шоссе, 0,82 → 0,79. Ограничения 1,3 и 1,6 дали одинаковую «горячесть», у 1,6 в маршрутах меньше основных дорог.

## 6. Сервер (maps-api)

- **Плечо:** две точки, не дальше 100 км по прямой (иначе 400 «leg too long»).
- **Очередь:** не больше 6 плеч одновременно в BRouter (`ROUTER_SLOTS`), остальные ждут по порядку. Состояние: `/maps/api/route/status`.
- **Лимит на клиента:** по IP. При 429 или 503 приложение повторяет запрос до 12 раз, параллельно у одного клиента не больше 3 плеч.
- **Кэш:** готовые плечи хранятся в SQLite (ключ: точки, профиль, все параметры, версия `ROUTE_CACHE_VER` = p5). Версию меняют, когда меняются профили.
- **400 «no track found»:** BRouter не нашёл пути между точками с этим профилем. Обычно точка стоит далеко от подходящей дороги или в закрытой зоне.

## 7. Время в пути

Код: `src/lib/eta.ts`, `routeMinutes`. Время в движении, без остановок. Считается по каждому отрезку профиля с его уклоном (сглаженным по окну 100 м) и покрытием, затем суммируется.

### Велосипед

Скорость v на отрезке находится из баланса мощности:

```
η·P = v · ( m·g·(sin θ + Crr·cos θ) + ½·ρ·CdA·v² )
η = 0,97 (трансмиссия), g = 9,81, ρ = 1,2 кг/м³, θ = atan(уклон)
```

- **Мощность в гору:** P × (1 + min(0,3, 5 × уклон)), то есть до +30 % с уклона 6 %. Любители на подъёмах работают сильнее, чем на равнине.
- **Мощность под гору:** P × max(0, 1 + уклон/0,04), на −4 % и круче не крутят.
- **Скорость на спуске:** не ниже скорости по ровному на том же покрытии и не выше потолка покрытия.
- **Нижняя граница:** 1,2 м/с (ведёт велосипед).
- **Поправка на реальность:** время × 1,2 за перекрёстки, повороты, разгоны и ветер.

| | Масса, кг | CdA, м² | P, Вт |
|---|---|---|---|
| Road | 83 | 0,32 | 150 |
| Gravel | 86 | 0,38 | 118 |
| MTB | 90 | 0,45 | 130 |

**Crr по покрытиям:**

| Покрытие | Road | Gravel | MTB |
|---|---|---|---|
| асфальт | 0,005 | 0,006 | 0,009 |
| укатанный | 0,014 | 0,011 | 0,012 |
| гравий | 0,025 | 0,018 | 0,016 |
| грунт | 0,035 | 0,025 | 0,020 |
| тропа | 0,05 | 0,035 | 0,026 |
| неизвестно | 0,006 | 0,011 | 0,014 |

**Потолок скорости на спуске, км/ч:**

| Покрытие | Road | Gravel | MTB |
|---|---|---|---|
| асфальт | 50 | 45 | 40 |
| укатанный | 30 | 38 | 35 |
| гравий | 22 | 32 | 30 |
| грунт | 18 | 26 | 26 |
| тропа | 12 | 18 | 20 |
| неизвестно | 45 | 35 | 30 |

**Что получается (средняя в движении, км/ч):**

| | −8 % | −3 % | 0 % | +3 % | +6 % | +10 % |
|---|---|---|---|---|---|---|
| Road, асфальт | 41,7 | 33,3 | 25,0 | 15,1 | 10,3 | 6,6 |
| Gravel, укатанный | 31,7 | 27,5 | 18,8 | 10,6 | 7,3 | 4,8 |
| Gravel, тропа | 15,0 | 11,4 | 10,6 | 7,0 | 5,5 | 3,9 |
| MTB, тропа | 16,7 | 16,7 | 13,4 | 8,4 | 6,4 | 4,4 |


### Пешком

Функция Тоблера:

```
v = 6 · exp(−3,5 · |уклон + 0,05|) км/ч × 0,9 × (0,95 на тропе, 0,97 на грунте)
```

Быстрее всего на пологом спуске около −5 %: 4,6 км/ч. По ровному 4,3 км/ч, на −25 % 2,6 км/ч, на +25 % 1,8 км/ч. Множитель 0,9 подобран по реальным походам. Прежнее правило DIN 33466 (300 м вверх или 500 м вниз в час) сильно завышало время на длинных спусках.

### Чего модель не учитывает

- остановки и привалы;
- ветер и вес багажа;
- личную форму. Настройки темпа пока нет: в коде есть множитель `pace`, но в интерфейс он не выведен.
